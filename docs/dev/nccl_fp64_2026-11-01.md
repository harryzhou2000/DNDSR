# NCCL and FP64 tensor-core preliminary complement

Date:2026-11-01 (Asia/Taipei). Status: **complete within the declared preliminary scope**.

The NCCL provider (enabled by default for CUDA, explicitly disableable) uses
existing row/payload plans, prepared device
scratch and stream-enqueued transfer/unpack. MPI remains the default and setup
control plane. Public C++/Python selection and the caller contract are described
in [NCCL transfers](../architecture/NCCLTransfer.md).

Jacobi has an explicit ordinary-FP64 or FP64-MMA selection. The small shared
Algebra adapter uses double-input/double-accumulator8x8x4 MMA; CFV handles padded
tails, periodic vectors, boundary terms and the existing strided U/URec views.
WBAP remains ordinary FP64. See [device reconstruction](../architecture/DeviceReconstruction.md).

Implementation commits: `07b76ecb` adds the providers/kernels, `1b8ab8e2` corrects
a Python fixture's checkpoint layout, and `645cb134` drains an immediate launch
that fails after partial packing before releasing leases. Independent product
benchmarking was added in `2ba63af3`, with matched scalar/tensor warp mapping in
`fa5595ae`. Completion documentation follows those source commits.

Completed validation:

  np1/2/4/8. A fresh CUDA-ON/NCCL-OFF build also passes its np1/np2 CPU-payload
  tests, so the explicit opt-out is exercised rather than assumed.

  at np1 and1403 per np2 rank. Coverage includes all physical formats, CSR/empty

  gated overlap, stale epochs in unchecked mode, rejected-lease rollback,
  collisions/abort errors and mismatched NCCL communicator identities.
- Existing CFV fixtures pass in ordinary, tensor, NCCL and combined modes,

  work and limiter/characteristic/activation checks. Each mode reports5 cases

- Python modules are rebuilt and installed after source changes. Focused7 tests

  Torch/DLPack36 tests pass. The first Python failure was a mismatched test

Inspection of the compiled sm80 tensor-core object finds1 DMMA,0 HMMA,
15 DFMA,3 DMUL and3 DADD instructions. Actual-wrapper timing uses65536 cells,
np1/np2, degrees1/2,5/21 components and all three DOF layouts. All26 cases/234
trial rows complete with numerical gates passing. Maximum CPU-reference errors
are1.11e-16 for Jacobi and2.92e-16 after limiting.

On two GPUs, degree2/AoS, NCCL packed communication is0.047ms versus MPI
packed0.113ms at5 components, and0.078ms versus0.312ms at21 components. For5
components across the two-rank degree/layout cases, tensor Jacobi is1.66–1.88x
faster; for21 components, it is1.26–1.54x slower. Ordinary FP64 remains the
runtime default. The standalone16-shape product benchmark uses the same
warp/cell mapping for both kernels and independent CPU long-double oracles;
ratios range0.60–3.11x, demonstrating why product throughput is not an integrated
solver speedup. Its earlier unmatched block mapping is superseded evidence.

An11,010,048-byte contiguous public-binding baseline passes exact oracles for
MPI/NCCL direct/packed paths. Median times are8.741/9.300ms for MPI direct/packed
and0.913/1.180ms for NCCL direct/packed. These include Python/C++ submission
overhead and the providers' actual scheduling contracts, not pure bandwidth.
NCCL reports SHM/direct; no NVLink, GPUDirect or multi-node performance is implied.
